# DDR-002: Navigation Strategy — Sidebar + Command Palette

## Status
Accepted

## Date
2026-07-13

## Decision Makers
- Chief Design Officer
- Principal UX Architect
- Principal Design System Architect
- Principal Frontend Architect

## Problem
Define how users navigate across 12 workspaces and within workspaces, balancing discoverability, speed, and scalability.

## Context
- 12 workspaces grouped into 4 clusters: Discover, Operate, Intelligence, Platform
- Users range from novice farmers to expert administrators
- Must support keyboard-first power users and touch-first mobile users
- Future: Android/iOS native apps with same IA

## Decision
**Primary Navigation:** Persistent Sidebar (left) with 4 visual groups
**Power Navigation:** Command Palette (`Cmd/Ctrl+K`) — fuzzy search all routes + actions
**Contextual Navigation:** Breadcrumb + In-page links + Related actions

### Sidebar Structure
```
DISCOVER
  🌐 Public
  👤 Customer
OPERATE
  📦 Orders
  🧪 Products
  🎓 Training
INTELLIGENCE
  ✨ AI Workspace
  🛡️ Governance
  📈 Analytics
PLATFORM
  ⚙️ Administration
  📝 CMS
  💬 Support
  🔧 Settings
```

### Command Palette (`Cmd/Ctrl+K`)
- **Modes:** Navigate / Actions / Recent / Favorites
- **Sources:** All workspace routes + quick actions + recent items + pinned
- **Ranking:** Recency + frequency + textual match
- **Keyboard:** `↑/↓` navigate, `Enter` execute, `Esc` dismiss
- **Accessibility:** Focus trap; `aria-label`; screen reader announces count

### Breadcrumb
- Always visible below header (except workspace root)
- Format: `Workspace › Section › Detail`
- Last item = current page (not link)
- Collapses to `… › Current` on narrow viewports

## Alternatives Considered

| Alternative | Pros | Cons | Why Rejected |
|-------------|------|------|--------------|
| Top Tabs (Workspace) | Visible always | Doesn't scale to 12; no hierarchy | Workspace count |
| Mega Menu | Dense | Mobile unusable; hover-only | Mobile-first |
| Hamburger Only | Clean | Low discoverability; extra tap | Power users need speed |
| Search-Only | Minimal | No browsing; no mental model | Novices need structure |

## Consequences

### Positive
- **Sidebar:** Always visible orientation; scales to 20+ workspaces; muscle memory
- **Command Palette:** Power-user speed; single keystroke to anywhere; discoverable via header button
- **Breadcrumb:** Orientation + one-click up-navigation
- **Unified:** Same IA for web, Android (bottom nav + drawer), iOS (tab bar + more)

### Negative
- Sidebar consumes horizontal space (mitigated by icon rail on tablet)
- Command Palette requires learning (mitigated by header button + `Cmd+K` hint)
- Breadcrumb adds vertical space (32px)

### Risks
- **Sidebar overload:** >12 workspaces → consider collapsible groups
- **Palette discoverability:** Non-power users may not find → Header search button + onboarding tooltip
- **Mobile drawer:** Extra tap to open → Persistent header workspace switcher

## Implementation
- `Sidebar` component: renders groups + items; `NavLink` for routes; active state highlighting
- `CommandPalette`: Portal-mounted; fuzzy search (Fuse.js); keyboard trap; recent/favorites in localStorage
- `Breadcrumb`: Auto-generated from route hierarchy; `NavLink` for each crumb
- `Header`: Workspace switcher (avatar menu); search trigger; palette trigger; profile menu
