# DDR-006: Accessibility Standard — WCAG 2.2 AA

## Status
Accepted

## Date
2026-07-13

## Decision Makers
- Chief Design Officer
- Principal Accessibility Architect
- Principal Design System Architect
- Principal Frontend Architect

## Problem
Establish the accessibility baseline that every component, page, and workflow must meet. No exceptions.

## Context
- Primary users: Indian farmers (low-end Android, low literacy, bright sun)
- Secondary: Enterprise admins (desktop, high-DPI)
- Legal: WCAG 2.2 AA compliance required for enterprise/government contracts
- Technical: React + TypeScript + Vite; future Android/iOS native

## Decision
**Mandatory Conformance: WCAG 2.2 Level AA**

### 1. Four Principles — All Must Pass

#### Perceivable
- **1.1.1 Non-text Content:** All images/icons have `alt` or `aria-hidden="true"`
- **1.2.1 Audio/Video:** Captions for video; transcripts for audio
- **1.3.1 Info & Relationships:** Semantic HTML; ARIA only when HTML insufficient
- **1.3.2 Meaningful Sequence:** DOM order = visual order
- **1.3.3 Sensory Characteristics:** No "click the green button" — use position + label
- **1.4.1 Use of Color:** Color not sole indicator (icons, patterns, text)
- **1.4.3 Contrast (Minimum):** 4.5:1 text; 3:1 UI components; 3:1 focus ring
- **1.4.4 Resize Text:** 200% zoom — no horizontal scroll; no content loss
- **1.4.10 Reflow:** 320px width — no horizontal scroll; content reflows
- **1.4.11 Non-text Contrast:** UI components 3:1; focus 3:1
- **1.4.12 Text Spacing:** Line 1.5x; paragraph 2x; letter 0.12em; word 0.16em
- **1.4.13 Content on Hover/Focus:** Dismissible; hoverable; persistent

#### Operable
- **2.1.1 Keyboard:** All functionality keyboard accessible
- **2.1.2 No Keyboard Trap:** Focus never trapped (except modal)
- **2.1.4 Character Key Shortcuts:** No single-key shortcuts (except Command Palette)
- **2.2.1 Timing Adjustable:** No time limits (except real-time)
- **2.2.2 Pause/Stop/Hide:** Auto-updating content pauseable
- **2.3.1 Three Flashes:** No content flashes >3Hz
- **2.4.1 Bypass Blocks:** Skip link to `#main` on every page
- **2.4.2 Page Titled:** Unique, descriptive `<title>`
- **2.4.3 Focus Order:** Tab order = visual order
- **2.4.4 Link Purpose:** Link text describes destination
- **2.4.5 Multiple Ways:** Search + nav + breadcrumbs
- **2.4.6 Headings/Labels:** Descriptive; unique per page
- **2.4.7 Focus Visible:** 3px solid ring; offset 2px; `outline-offset: 2px`
- **2.5.1 Pointer Gestures:** No multipoint/path gestures required
- **2.5.2 Pointer Cancellation:** Down-event not execute; up-event cancels
- **2.5.3 Label in Name:** Accessible name includes visible label
- **2.5.4 Motion Actuation:** No motion-only actions

#### Understandable
- **3.1.1 Language of Page:** `<html lang="en">` (+ `lang` on partials)
- **3.2.1 On Focus:** Focus ≠ navigation; no unexpected context change
- **3.2.2 On Input:** Input ≠ submit; no auto-submit
- **3.2.3 Consistent Navigation:** Nav order consistent across pages
- **3.2.4 Consistent Identification:** Same component = same label/role
- **3.3.1 Error Identification:** Errors identified + described in text
- **3.3.2 Labels/Instructions:** All inputs have labels + hints
- **3.3.3 Error Suggestion:** Error message suggests fix
- **3.3.4 Error Prevention (Legal/Financial):** Confirmation + review + reversible

#### Robust
- **4.1.1 Parsing:** Valid HTML; no duplicate IDs; proper nesting
- **4.1.2 Name/Role/Value:** All components have name, role, state
- **4.1.3 Status Messages:** `aria-live="polite"` for success; `assertive` for errors

### 2. Component-Level Requirements

| Component | Required ARIA | Keyboard | Focus Mgmt |
|-----------|---------------|----------|------------|
| Button | `role="button"` (native) | Enter/Space | Focus ring |
| Link | `<a href>` (native) | Enter | Focus ring |
| Input/Textarea | `<label for>` + `aria-invalid`/`aria-describedby` | Tab | Error focus |
| Select | `<select>` / Combobox (`role="combobox"`) | Arrows, Enter, Esc | Focus in listbox |
| Checkbox | `<input type="checkbox">` + `<label>` | Space | Focus ring |
| Radio Group | `<fieldset>` + `<legend>` + `<input type="radio">` | Arrows | Focus ring |
| Switch | `role="switch"` + `aria-checked` | Space | Focus ring |
| Tabs | `role="tablist"` + `role="tab"` + `role="tabpanel"` | Arrows, Home, End | Auto-activate on arrow |
| Modal/Dialog | `<dialog>` or `role="dialog" aria-modal="true"` | Trap; Esc closes | Focus first; restore on close |
| Drawer | `role="dialog"` + `aria-modal="true"` | Trap; Esc closes | Focus first; restore |
| Dropdown/Menu | `role="menu"` + `role="menuitem"` | Arrows, Enter, Esc | Focus management |
| Tooltip | `role="tooltip"` + `aria-describedby` | Hover/Focus | — |
| Toast | `role="status"` (success) / `role="alert"` (error) | — | `aria-live="polite/assertive"` |
| Table | `<caption>` + `<th scope="col/row">` | Arrows (grid) | Focus cell |
| Data Grid | `role="grid"` + `role="row"` + `role="gridcell"` | Arrows, Home/End, Ctrl+A | Focus cell |

### 3. Testing Protocol

| Layer | Tool | Frequency | Threshold |
|-------|------|-----------|-----------|
| **CI Automated** | axe-core (JSDOM) | Every PR | 0 violations |
| **Storybook** | storybook-addon-a11y | Per component | 0 violations |
| **CI Visual** | Chromatic + axe | Per PR | 0 violations |
| **Manual Keyboard** | Human | Per component + page | 100% tasks |
| **NVDA + Chrome** | Human | Per component + page | 100% announced |
| **VoiceOver + Safari** | Human | Per component + page | 100% announced |
| **JAWS + Edge** | Human | Critical paths | 100% announced |
| **Zoom 200%** | Manual | Per page | No horiz scroll |
| **Reduced Motion** | OS setting | Per component | Animations off |

### 4. Testing Scripts (Component)

```text
# Keyboard Test (5 min)
1. Tab to component
2. Verify focus visible (3px ring)
3. Tab through all interactive elements
4. Shift+Tab reverse
5. Enter/Space activates
6. Escape closes (modals/drawers)
7. Arrows navigate (tabs, menus, grids)
8. Home/End/PageUp/PageDown work
9. Escape closes (modals, drawers, dropdowns)
10. Focus returns to trigger on close

# Screen Reader Test (NVDA)
1. Navigate to component
2. Verify name announced (label/button text)
3. Verify role announced (button, link, textbox, etc.)
4. Verify state announced (checked, selected, expanded, disabled)
5. Interact (Enter/Space/Arrows)
6. Verify state change announced
7. No extra verbose announcements

# Screen Reader Test (VoiceOver)
1. Rotor → component
2. Swipe right → name + role + state
3. Double-tap → activate
4. Swipe → state change announced
```

### 5. Page-Level Test

```text
1. Page title unique + descriptive
2. Skip link works (Tab → "Skip to content" → Enter → #main focused)
3. Landmarks: banner, nav, main, aside, contentinfo
4. Heading hierarchy: H1 → H2 → H3 (no skips)
5. All images: alt text (decorative = alt="")
6. Forms: labels + hints + errors announced
7. Errors: inline + toast; focus first error
8. Language: <html lang="en">; partial lang="" where needed
```

## Alternatives Considered

| Option | Rejected Because |
|--------|------------------|
| WCAG 2.1 AA | 2.2 adds 2.4.11 Focus Not Obscured, 2.5.7 Dragging, 3.2.6 Consistent Help |
| WCAG 2.2 AAA | Unrealistic for data-heavy product; 7:1 contrast too restrictive |
| Section 508 Only | WCAG 2.2 AA is superset; international contracts need WCAG |
| Custom Standard | Legal risk; no external auditability |

## Consequences

### Positive
- **Legal safety** — Meets enterprise/gov contracts
- **Inclusive** — Works for farmers, elderly, disabled
- **Quality signal** — Accessibility = code quality proxy
- **SEO/SEM** — Semantic HTML + structure = better indexing

### Negative
- **Velocity cost** — ~15% dev time on a11y
- **Design constraints** — No color-only; no hover-only; focus visible mandatory
- **Testing overhead** — Manual SR testing per component

### Risks
- **False confidence** — Automated only catches ~30% → Manual mandatory
- **Screen reader fragmentation** — NVDA/JAWS/VoiceOver differences → Test all three
- **Mobile a11y** — TalkBack/VoiceOver gestures differ → Test on device
