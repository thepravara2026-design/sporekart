# DDR-001: Layout Strategy — App Shell + Sidebar + Content

## Status
Accepted

## Date
2026-07-13

## Decision Makers
- Chief Design Officer
- Principal UX Architect
- Principal Design System Architect
- Principal Frontend Architect

## Problem
Define the foundational layout architecture for the Enterprise Web Application that supports:
- 12 workspaces with distinct navigation
- Consistent orientation across all viewports
- Scalable information hierarchy
- Developer ergonomics (single layout component)

## Context
- 12 workspaces (Public, Customer, Orders, Products, Training, AI, Governance, Analytics, Admin, CMS, Support, Settings)
- Must work from 375px mobile to 1536px+ desktop
- Persistent navigation + context switching
- Future: native apps sharing same IA

## Decision
Adopt **App Shell** layout with three persistent regions:

```
┌─────────────────────────────────────────────────────────────┐
│  GLOBAL HEADER (56px) — Brand, Workspace, Search, Profile   │
├──────────────┬──────────────────────────────────────────────┤
│  WORKSPACE   │  BREADCRUMB BAR — Workspace › Section › Page  │
│  SIDEBAR     ├──────────────────────────────────────────────┤
│  (264px)     │  CONTENT AREA — Page title, Primary Action,   │
│              │  Panel (skeleton-matched)                     │
├──────────────┴──────────────────────────────────────────────┤
│  FOOTER — Legal, Help, Status, Version                       │
└─────────────────────────────────────────────────────────────┘
```

### Responsive Behavior

| Breakpoint | Sidebar | Header Search | Content Max-Width |
|------------|---------|---------------|-------------------|
| xs (<640)  | Drawer (280px) | Hidden (Cmd+K) | 100% |
| sm (640–767) | Drawer (280px) | Hidden (Cmd+K) | 100% |
| md (768–1023) | Icon Rail (72px, hover expand) | Hidden (Cmd+K) | 100% |
| lg (1024–1279) | Icon Rail (72px, hover expand) | Hidden (Cmd+K) | 1200px |
| xl (1280–1535) | Fixed 264px | Centered 420px | 1200px |
| 2xl (≥1536) | Fixed 264px | Centered 420px | 1400px |

## Alternatives Considered

| Alternative | Pros | Cons | Why Rejected |
|-------------|------|------|--------------|
| Top Tab Bar | Familiar; works on mobile | Doesn't scale to 12 workspaces; no hierarchy | Fails workspace count |
| Mega Menu (Hover) | Dense info | Mobile unusable; discoverability poor | Mobile-first required |
| Bottom Nav (Mobile) | Thumb-friendly | Doesn't scale to desktop; no workspace switching | Desktop parity required |
| Collapsible Tree Nav | Dense | Cognitive load; mobile unusable | Simplicity principle |

## Consequences

### Positive
- Single layout component (`AppShell`) for entire app
- Persistent orientation: users always know workspace + location
- Scales to 20+ workspaces without IA change
- Native app mapping: Sidebar → Tab Bar; Drawer → More tab
- Single code path for SSR + CSR hydration

### Negative
- Sidebar consumes horizontal space on desktop (mitigated by icon rail)
- Drawer on mobile adds tap (mitigated by Cmd+K palette)
- Header height fixed (56px) — content starts lower

### Risks
- **Sidebar width on tablet:** 72px icon rail may be too narrow for labels → Hover/focus expansion with 200ms transition
- **Drawer dismissal:** Swipe gesture + backdrop click + Escape key all required
- **Content max-width:** Prose 720px; Data 1200px; Dashboard full — requires container queries

## Implementation

- `AppShell` component (React) — single entry point
- `Header`, `Sidebar`, `Breadcrumb`, `Content`, `Footer` sub-components
- CSS Grid layout (`grid-template-rows: 56px 1fr auto; grid-template-columns: var(--sidebar-width) 1fr`)
- CSS Custom Properties for all dimensions (tokens)
- Responsive via `@media` + container queries for content panels
