# DDR-007: Design Token Architecture — Primitive → Semantic → Component

## Status
Accepted

## Date
2026-07-13

## Decision Makers
- Chief Design Officer
- Principal Design System Architect
- Principal Frontend Architect
- Principal Performance Engineer

## Problem
Define a token architecture that separates raw values from semantic meaning from component usage, enabling theming, multi-platform, and safe evolution.

## Context
- 12 workspaces, 50+ components, 4 themes planned (Light, Dark, High Contrast, Brand)
- Multi-platform: Web (React), Android (Compose), iOS (SwiftUI) — single source
- Designers in Figma (Tokens Studio); Developers in VS Code
- Must support: Light/Dark/High Contrast/Brand themes; Print; Email; Native apps

## Decision

### 1. Three-Layer Architecture

```
┌─────────────────────────────────────────────────────────────┐
│  PRIMITIVES (Raw Values)                                    │
│  green-50..950, neutral-50..950, spacing-base: 4px, etc.    │
│  Never used directly in components                          │
├─────────────────────────────────────────────────────────────┤
│  SEMANTIC ALIASES (Meaning)                                 │
│  color.primary.default, spacing.component-gap,              │
│  radius.card, elevation.level-1, fontSize.body              │
│  Theme-specific overrides live here                         │
├─────────────────────────────────────────────────────────────┤
│  COMPONENT TOKENS (Usage)                                   │
│   button.primary.bg.default, input.border.color.focus,      │
│   card.radius.default, table.row.height.compact             │
│  Consumed by components; never raw primitives               │
└─────────────────────────────────────────────────────────────┘
```

### 2. Token Categories & File Structure

```
tokens/
├── color.json           # Primitives + Semantic + Component
├── typography.json      # Font families, sizes, weights, line heights, tracking
├── spacing.json         # Base unit, scale, semantic (padding, gap, layout)
├── radius.json          # Scale + component mappings
├── elevation.json       # Shadows, surfaces, backdrops, z-index
├── border.json          # Widths, styles, colors
├── opacity.json         # Scale + semantic (disabled, overlay)
├── animation.json       # Durations, easings, motion reduction
├── sizing.json          # Icons, illustrations, containers, components
├── breakpoints.json     # xs, sm, md, lg, xl, 2xl
├── z-index.json         # Layer hierarchy
├── misc.json            # Font families, transitions, etc.
├── index.json           # Manifest + metadata
└── themes/
    ├── light.json       # Light theme overrides
    ├── dark.json        # Dark theme overrides
    ├── high-contrast.json
    └── brand-{partner}.json
```

### 3. Naming Convention (CTI-Inspired)

```
{category}.{property}.{variant}.{state}.{scale}
```

| Part | Values | Example |
|------|--------|---------|
| **category** | `color`, `typography`, `spacing`, `radius`, `elevation`, `border`, `opacity`, `animation`, `breakpoint`, `zIndex`, `sizing` | `color` |
| **property** | `bg`, `text`, `border`, `icon`, `shadow`, `surface`, `overlay`, `focus`, `skeleton`, `fontFamily`, `fontSize`, `fontWeight`, `lineHeight`, `letterSpacing`, `padding`, `margin`, `gap`, `inset`, `radius`, `width`, `height`, `icon`, `illustration`, `container`, `duration`, `easing`, `breakpoint`, `zIndex` | `bg` |
| **variant** | `primary`, `secondary`, `success`, `warning`, `danger`, `info`, `neutral`, `surface`, `overlay`, `focus`, `skeleton`, `onPrimary`, `onSurface` | `primary` |

### 3. Primitive vs Semantic vs Component

| Layer | Example | Consumers |
|-------|---------|-----------|
| **Primitive** | `color.green.600: "#2F6F4F"` | **Never** directly in components |
| **Semantic** | `color.primary.default: "{color.green.600}"` | Theme builders, global styles |
| **Component** | `button.primary.bg.default: "{color.primary.default}"` | Component implementations |

### 4. Theme Override Chain

```
Base (Light) → Theme Override (Dark) → Component Token
```

```json
// tokens/themes/dark.json
{
  "color": {
    "background": { "default": "{color.neutral.950}" },
    "surface": { "default": "{color.neutral.900}", "raised": "{color.neutral.800}" },
    "border": { "default": "{color.neutral.700}" },
    "text": { "primary": "{color.neutral.50}", "secondary": "{color.neutral.400}" },
    "primary": { "default": "{color.green.400}", "hover": "{color.green.300}" },
    "focus": { "ring": "{color.green.400}" },
    "skeleton": { "base": "{color.neutral.800}", "highlight": "{color.neutral.700}" }
  }
}
```

### 5. Theme Switching Implementation

```css
/* CSS Custom Properties generated from tokens */
:root {
  --color-bg-primary-default: #2F6F4F;
  --color-bg-primary-hover: #265D3F;
  --color-text-primary: #1D2B22;
  /* ... */
}

[data-theme="dark"] {
  --color-bg-primary-default: #66BB6A;
  --color-bg-primary-hover: #81C784;
  --color-text-primary: #FAFAFA;
  /* ... */
}

/* High Contrast — CSS-only, no JS */
@media (forced-colors: active) {
  :root {
    --color-background: Canvas;
    --color-surface: Canvas;
    --color-text-primary: CanvasText;
    --color-text-secondary: CanvasText;
    --color-border: CanvasText;
    --color-primary: Highlight;
    --color-focus-ring: CanvasText;
    --color-danger: #FF0000;
    --color-success: #00FF00;
  }
  .btn-primary { background: Highlight; color: HighlightText; border: 2px solid CanvasText; }
  .input { background: Canvas; color: CanvasText; border: 2px solid CanvasText; }
}
```

### 5. React Theme Context (Future)

```tsx
const ThemeContext = createContext<'light' | 'dark' | 'system'>('system');

function ThemeProvider({ children }) {
  const [theme, setTheme] = useState<'light' | 'dark' | 'system'>('system');
  
  useEffect(() => {
    const root = document.documentElement;
    if (theme === 'system') {
      const prefersDark = window.matchMedia('(prefers-color-scheme: dark)').matches;
      root.dataset.theme = prefersDark ? 'dark' : 'light';
    } else {
      root.dataset.theme = theme;
    }
  }, [theme]);
  
  return <ThemeContext.Provider value={{ theme, setTheme }}>{children}</ThemeContext.Provider>;
}
```

## Alternatives Considered

| Option | Rejected Because |
|--------|------------------|
| Flat token list (no layers) | No theming; hardcoded values in components |
| Two layers (Primitive → Component) | No semantic meaning; can't theme |
| CSS Variables only | No type safety; no Figma sync; no multi-platform |
| SCSS Variables | Not portable to Android/iOS; no design tool sync |
| Single theme file | Can't support Dark/HC/Brand cleanly |

## Consequences

### Positive
- **Themeable by design** — Dark/HC/Brand via overrides only
- **Multi-platform** — JSON → CSS vars + TS types + Compose XML + SwiftUI
- **Type-safe** — TS types generated from JSON
- **Figma sync** — Tokens Studio reads/writes same JSON
- **Auditable** — Every color traceable to primitive
- **Performant** — CSS vars resolved at runtime; no JS overhead

### Negative
- **Complexity** — Three layers + themes = more files
- **Learning curve** — Teams must understand hierarchy
- **Build step** — Token build pipeline required (Style Dictionary)

### Risks
- **Token drift** — Code vs Figma drift → Automated diff in CI
- **Over-abstraction** — Too many semantic tokens → Audit quarterly
- **Theme coupling** — Component tokens must not leak theme logic
